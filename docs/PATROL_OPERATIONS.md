# 巡回の確認・停止商品の再開

登録商品の価格・在庫はworkerがサイト別adapterで確認します。RecordCityも実装対象です。実装があることと、全商品が現在正常に巡回できていることは別に確認します。

## 失敗・停止した商品

- SNKRDUNKのURL形式と対象商品を検証します。中古商品へ親商品の集計価格や別商品の値を流用しません。
- 不正URLは `patrol_paused_reason=invalid_url` として巡回対象から外します。既存の価格・在庫・失敗履歴を消して正常と扱いません。
- 商品編集画面で正しいURLへ修正し、明示的に巡回を再開します。同一利用者・ショップの重複や別商品へのすり替えは拒否します。
- 失敗数が解消されることは、再開操作だけでなく、実際の取得成功で確認します。
- アクセス制限や根拠不足の応答は、確認できた直前値を保ち、監視の理由・時刻を確認します。

## 抽出の途中結果

RecordCityの一覧・詳細処理では、実進捗と検証済みの途中結果を保存します。途中結果は商品の自動登録ではなく、画面で選択して登録するためのものです。失敗後も再読込して取得済みの結果を確認できます。

heartbeatはプロセスの生存確認であり、取得件数や有効な価格・在庫の証拠ではありません。RQの失敗・停止とDB/UIの終了理由、監視の記録を照合します。強制終了まで含む厳密な一度だけの保存を保証するものではありません。

## 運用確認

1. web/workerのGit SHAとAlembic revisionを一致させる。
2. `/readyz`の接続状態と、`/stack-readyz`のworker・scheduler・巡回完了時刻を確認する。
3. 管理画面 `/admin/scrape-health` でサイト別・経路別の実結果を確認する。
4. 代表商品で価格・在庫・画像を確認し、停止商品の修正・再開が成功したことを記録する。

サイトに対象商品がない場合、未観測を成功とみなしません。更新件数と取得成功件数も区別します。通知・取得率の詳細は [監視手順](SCRAPE_MONITORING_RUNBOOK.md)、継続中のworker修正は [納品確認一覧](DELIVERY_STATUS.md) を参照してください。
