# 巡回・抽出ジョブの信頼性改善（2026-09-29）

関連: [#173](https://github.com/halc8312/ESP/issues/173)、[#174](https://github.com/halc8312/ESP/issues/174)。調査時の本番コードは `72a8e6df47ebd9ec2bf4d4047b4511f325ec4317`。

## 確認できた原因と調査限界

- SNKRDUNK の `/apparels/{id}` と `/apparels/{id}/used/{id}` が、巡回の URL 検証で取得前に拒否されていた。本番 worker の 9 月 29 日のログで確認した。巡回側と HTTP 取得側の両方に `/products/` のみを許可する処理があった。
- 同じ不正 URL に対してバックオフ後も巡回を繰り返し、失敗が増え続ける構造だった。報告された失敗数そのものは、今回のログ調査では照合できていない。
- 9 月 14 日の約 20 分後のジョブ停止は、取得できたログの保存範囲外で原因未確定。入力 URL・ジョブ ID・当時の DB/RQ 状態も照合できていない。タイムアウト延長で解決したとは扱わない。
- コード上では、RecordCity の途中取得結果がジョブ完了前に保存されず、RQ の失敗・停止も直ちに DB/UI に反映されない問題を確認した。

## 今回の変更

### SNKRDUNK 巡回

- URL の形式と商品識別を共通化し、既存の sneaker 商品に加えて apparel / used 商品を検証対象にする。ドメインやプロトコル等の既存制限は維持する。
- apparel の構造化データは対象 URL と一致する商品だけを採用する。used 商品へ親商品の集計価格や推奨商品の情報を流用しない。同一性や価格・在庫の根拠が不足する場合は、直前の確認値を保持する。
- 真に不正な URL は `patrol_paused_reason=invalid_url` として保存し、以後の巡回対象から外す。停止時に失敗を 1 回記録し、価格・在庫・失敗履歴を消さない。
- 商品編集画面で URL を修正し、明示的に巡回を再開できる。同じ利用者・ショップの既存商品との重複や、識別可能な SNKRDUNK 商品を別商品へ差し替える操作を拒否する。
- URL の対応範囲が増えた場合もローカル検証で再開可能にする。失敗数をリセットするのは取得が成功した時点。

### RecordCity ジョブの途中結果

- 一覧ページと商品詳細の処理後に、実際の進捗を DB に保存する。生存確認の heartbeat は取得件数を増やさない。
- 検証・重複除外・利用者の除外条件・価格条件を適用した商品を、所有者に紐づくジョブの途中結果として保存する。
- 途中結果は商品テーブルへの自動登録ではない。失敗後も画面を再読込して、保存済みの商品から選んで登録できる。
- RQ の failed / stopped / canceled をジョブの終了理由へ反映し、監視にも記録する。終了済みの状態と結果を遅れて届いた更新で上書きしない。
- heartbeat の一時的な DB 書込みエラーで heartbeat スレッドが終了しないようにする。書込み失敗を成功した生存確認として扱うことはしない。

## 適用・運用上の注意

- Alembic `20260929_0023` は products に nullable な停止理由・停止時 URL の 2 列を追加する。旧 head からの更新と既存行の保持、再実行を検証する。
- web / worker は同じ変更へ揃え、新コードが product を読む前に通常の migration 手順で列を追加する。Render の split 構成や環境変数は変更しない。
- コードをロールバックする場合も追加列を残せる。停止情報を消す downgrade を通常のロールバックとして実行しない。
- この変更では既存商品の URL や過去の失敗数を一括更新しない。修正後の巡回で確認する。

## 検証記録

- ローカル Python 3.12 の全体試験は 1902 passed / 1 skipped / 1 failed。失敗は既存の RecordCity キーワード検索テストの代替関数が、新しい `progress_callback` 引数を受け取らないためだった。代替関数を更新し、コールバックが渡ることも確認する形に修正後、当該ファイルの 15 件はすべて成功した。
- 全体試験はネットワーク接続を実行前に拒否する設定で実施。プレビュー登録テストは対象外の翻訳処理を代替し、翻訳モデルを取得しない。翻訳機能自体の既存テストは別途含まれている。
- 独立レビューで、対象が一致する売り切れ Offer の価格省略と、終了済みジョブから遅れて返った結果の扱いを修正した。待機画面から途中結果を回収する導線も確認した。
- JavaScript 構文、差分形式、依存パッケージ整合性を確認済み。GitHub の全体 CI / Docker 検証と本番巡回の結果は、対応 PR に記録する。

## 残る検証・後続作業

- apparel / used の解析テストは合成 HTML による回帰検証であり、現行の実サイト取得成功を証明するものではない。デプロイ後、通常の巡回で価格・在庫を確認できるか観測する必要がある。
- #174 は継続する。進捗が止まったまま heartbeat だけが続く場合の独立した判定、アクセス制限待ちの表現、継続位置からの冪等な再開は今回の範囲外。
- 商品保存の直前に実行状態を確認し、監視への観測はジョブの終了確定後に行う。ただし商品保存とジョブ完了は別トランザクションのため、保存処理中の強制終了まで含めた原子的な完了・厳密な一度だけの副作用は保証しない。この境界も #174 の後続対象とする。
- 途中結果の通知は今回 RecordCity の検索に追加した。他サイトへの展開と一覧情報だけの取得は #177 / #178、取得率・重複による成功判定は #175 に分ける。
- 300〜500 件対応、サイト別の共有実行制限、RecordCity 登録商品の巡回は、それぞれ #181 / #176 / #180 で扱う。
- 外部サイトへアクセスする統合試験、実 PostgreSQL の競合試験、実 Redis/RQ のプロセス強制終了試験はローカルのオフライン試験で代替できない。
